**G3a — CORRECTED by the 21:5x audit: the earlier "no engine behind PAUSED" claim was wrong.** The
byte-continuation exists and is wired end to end:
- `android/app/src/main/python/downloader.py` (698 lines): `class PausedError` keeps the partial; the

- `DowniDownloadService`: `isPaused()`/`supportsPause()` on the headless path, `handlePaused` persists

  from bytes"), `maybeStop` keeps the service alive while paused, and the interruption sweep makes a
  process-killed transfer resumable when bytes exist on disk.
- Production doors: the grab notification's **Pause/Resume** actions (`drop*` jobs only),
  `resumeAllPaused` (card "Resume all paused grabs"), the per-job Resume button, the Core's own tap
  (`CoreTapAction` PAUSED→RESUME → `shared_resume`), and `shared_resume_latest`.
- `CoreJobBinding.viewFor`: a `paused` row → `CoreStates.PAUSED`, and it never ages out.
- The bench commands (`core.cmd pause|status|resume`) sit behind `pollCoreCmd`'s `BuildConfig.DEBUG`
  guard (L1196) — the visual half never ships.

**R2 (approved): do not fake pause.** D3 ships in v3.3 only if the full device matrix passes (Wave 5);

## §4 The device standard, applied per reference

A reference is **closed** only when all three are true:
**CODE** (in the shipping source, never a debug-only path) · **WIRED** (driven by live truth, with the
log line that proves which truth) · **PROVEN** (captured on the vivo V2058, the frame or number named
in `DEVICE_TEST.md`, signed by the owner).

| Ref | The live truth that must drive it | The log line | The capture |
|---|---|---|---|
| C1 | the window/geometry + the state | `CORE_ATTACH … type=2032 size_dp=`, `CORE_STATE` | 48/56/64 dp + paused bars |
| C2 | **measured route health** (never a flag) | `CORE_DETECT detected=true grade=ready\|aware`, `CORE_STATE wake` | the 600 ms frame series, READY vs AWARE |
| C3 | real touch events | `CORE_TOUCH down/up dragging=` | press / rebound / slosh / edge-catch measurements |
| C4 | the resolver's real beats | `RUN_STEP`, `CHAIN_*` | ENGAGE / REACH / STEPS / CAPTURE frames |
| C5 | the engine's real job | `CORE_JOB state=… pct=…` | one capture per lifecycle state, incl. PEEK |
| C6 | the engine's real failure/refusal | run's terminal line, `CORE_UNSUPPORTED` | rose hold + neutral (unsupported) frames |

**Anti-patterns (explicitly disallowed in v3.3):** driving a reference with the bench channel in a
release build; a state that exists only because a sheet shows it; a percentage drawn as text; a
"pause" that is not actually frozen; an error that flashes or turns red; a tether that lands anywhere
other than the control the resolver really touches.

**The pause/return truth (R2/R6):** PAUSED may appear on the Core only while a real `paused` row
exists (the notification's Pause action, or the interruption sweep after a process kill with bytes on
disk); RESUMING may appear only when a resume was really requested (the Core's own tap that sent
`shared_resume`); RETURN keeps its 20 s hold, then fades. Any capture showing PAUSED or RESUMING
without the matching service line is a defect, not a demo.
