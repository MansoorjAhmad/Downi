### F3 — the instrument grows the two things it was missing

`tools/core_web_audit.py` is Part 3's own tool, so its blind spots are Part 3's problem:

- **`hit`** — for every control, the box of the nearest ancestor that actually receives the tap
  (`label`/`button`/`a`/`[onclick]`/`[role=button]`). A 20 px checkbox inside a 53 px `<label>` row is
  then *measured honestly* instead of being called a defect; the raw count is still printed, so nothing
  is hidden. Every table carries both numbers: **raw / hit-aware**.

  pushed sideways by a wider pill; now it can, and F2 is gated on it reading 0.

**Gate.** The tool's own docstring records the change; the four-screen table is re-run under the new rule
so every before/after pair is like for like (the baseline is re-measured, not re-labelled).

### F4 — M3: the state vocabulary gets a type and a transition rule *(the last "Not started" milestone)*

**What is actually wrong today** (not a rename: a duplicated truth no test can see):

1. `CoreStates` is 14 string constants + three predicates. The **kind** of a state (a one-shot transient
   vs a look that holds until the truth changes vs a state the finger owns) is implied by whichever
   predicate list it appears in.
2. `CoreHost.settle()` **hardcodes** what each transient becomes (`WAKE→DETECTED`, `RESUMING→PROGRESS`,
   `COMPLETING→COMPLETE`, `RETRY→RESOLVING`) — a *second* copy of knowledge that `isTransient()` also
   holds. Nothing checks the two agree; a new transient with no settle target would freeze silently.
3. `DowniCore.setBaseState()` carries the "never cut a transient" guard inline, and the arbiter's own rule
   (its verdict must be a *hold* state) is a comment, not a check.
4. `CoreHost.setState()` accepts any known state from any caller — including the debug channel — with no
   record when the transition was illegal. The gates read `CORE_STATE` lines and cannot see a violation.

**The change.** One table, read by both sides:

- `CoreStates.Kind` — the explicit type: `REST`, `TRANSIENT`, `HOLD`, `TOUCH`.
- `CoreStates.settleTarget(s)`, `isHold`, `isTouch`, `interruptible(s)` — derived from that one table.
- `CoreStates.isLegal(from, to)` — the documented transition table, including the two hard rules that
  until now lived in prose: **a transient is never cut** and **the arbiter may only name a hold state**.
- `CoreHost.settle()` reads `settleTarget` (its hardcoded chain goes away).
- `CoreHost.setState()` reports an illegal transition on **one line**, debug builds only:
  `CORE_TRANSITION from=x to=y legal=false` — visible to the rigs, invisible to a user.
- `CoreArbiter.baseState()` keeps its signature; its contract is asserted, not implied.

**Wire names do not change.** `CoreStates.list()` and every `CORE_STATE` line keep today's spelling
exactly; the debug channel, the gates and the service are untouched. Zero user-visible change.

**Gate.** A new JVM suite (`CoreStatesTest`) pinning: the 14 names and their order (the vocabulary cannot
change silently), every transient has a settle target, every settle target is a hold state, the arbiter's
three verdicts are holds, the touch states override but return, and the illegal pairs (cut a transient;
the arbiter naming a touch/transient state) are refused. Suite count **17 → 18**. Then the M7 regression
on the fixed build: the same `CORE_STATE` lines as before, `VERDICT 0`.

### F5 — the last `infinite` declaration gets priced

`.bar.live > div::after` sweeps for the whole life of a job. `V3.3.1_PLAN.md` §5 kept it ("bounded, one
instance, stops with the job") and asked for a price "with a held-open job". A held-open job is not

the way the vortex was priced: put the exact class on a visible screen through the page's own DevTools

**Limit, stated up front:** this prices the CSS animation, not a real download window (which also burns
CPU in the embedded Python engine — the reason §0k-7 refused to attribute that window). Both numbers go
into the cell, labelled for what they are.
