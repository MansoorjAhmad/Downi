## 0. The answer in one paragraph

Two independent causes, in this order.

**1) The binary on the phone is stale.** The installed `base.apk` is byte-identical (SHA-256 `66a5d2fa…`)
to the local `android/app/build/outputs/apk/debug/app-spike-signed.apk` built **2026-09-26 20:19:44**.
Everything from the 20:25 reach commit onward is *not on the phone*: the committed reach wiring (Wave 2),
Wave 3, and Wave 4. **Wave 4 has never been compiled into any APK at all** — its symbols
(`WAKE_BEATS_MS`, `wakeStage`, `RELEASE_SETTLE_MS`, `releaseSettle`, `returnFade`) are absent from *both*
existing APKs, including the newer 20:47 `app-debug.apk` (SHA-256 `5a4449a5…`) that was never installed.

**2) Even the current source's face cannot produce C1 — it is drawn in the wrong visual vocabulary.**
The whole visible Core is one canvas, `CoreHost.onDraw` (L402-518): a near-perfect circle (≤5 % lobing),
thin stroked rims (1.6 dp band under a 2.2 dp stroke), a ≤17 %-alpha bloom, a 24 %-white gloss blob, and
the mark as a flat circle-clipped bitmap. Measured on the real device: ring = a solid **2.2 dp #3B82F6
stroke**, interior = flat **#0D1C2C**, glyph = washed pale teal ≈18 dp tall. That vocabulary is
*structurally the same* as the pre-9/25 face; `b08879d` ("the face rebuilt to the sheets", 9/25 22:47)
changed **parameters** (circle → 3 % blob, linear rim → sweep rim, 1.6 → 2.2 dp, +bounce +gloss), not the
language. At 42.5 dp on screen it reads "flat badge" = the old Fetcher, no matter how the tables are tuned.

This is **not** a state/wiring bug: states, grades, progress, pause bars and reach all render live per the
tables (captures below). The gap is **stale binary + material vocabulary**.

## 2. What the approved C1–C6 references require (the targets)

- **C1 — Material & Identity:** a *physical* glossy obsidian gel object: a **thick translucent cyan
  membrane as part of the material** (a band wrapping the silhouette), a **physical rim with depth and
  thickness**, a large top-left specular, an **organic, non-circular silhouette**, a large folded-ribbon
  chevron **embedded** (under the glass, lit by it), paused = bars replacing the chevron, dense/heavy/premium.
- **C2 — Wake:** staged activation at 100/200/300/400/600 ms; AWARE vs READY; **no generic ring**.
- **C3 — Physics:** ~10 % press compression, rebound, drag slosh with chevron trail, edge catch
  (compress + bulge), restrained settle.
- **C4 — Reach:** tether to the *real* control, travelling node, orbit at the chain steps, capture flash, return.
- **C5 — Ring:** perimeter = real progress; frozen pause; resume; completing collapse; complete/peek; RETURN fade.
- **C6 — Failure:** restrained rose — never an alarm; retry; neutral blue/grey unsupported.

## 5. Which are wired but not visually apparent

- **C3 physics**: a 10 % compression is ~4 px on a 42.5 dp object, the slosh lag is 4 px — the gel

- **C2 AWARE vs READY**: differs in the tables (halo 0.30 vs 0.85, rim 0.78 vs 1.00) but both render as

- **C4 orbit steps / tether**: renders — as thin arcs and strings *over* the app, not as energy leaving
  an object; reads as UI overlay, not the sheet's choreography.
- **C6 failure / unsupported**: the tint changes (rose / neutral) on the same flat anatomy; no capture in
  this audit proves the on-device read (installed build has the code: `setUnsupported`).

## 7. The exact renderer/path responsible for the old appearance

One canvas, no second renderer. Path: `res/xml/fetcher_service.xml` → `DowniFetcherService`
(`extends AccessibilityService`, manifest L70-82; the only a11y service) → `DowniCore` (the window host:
`TYPE_ACCESSIBILITY_OVERLAY`, attach-once, 48/56/64 dp; constructed at `DowniFetcherService` L317/L523/L1208)
→ **`CoreHost` (the View; the entire visible Core)** → `CoreLook.of()` tables → `CoreMotion` timings.
Grep proves no old bubble class survives (no `Bubble`/spike renderer in `src/main`).

`CoreHost.onDraw` (L402-518) vocabulary, in draw order: halo RadialGradient (idle `0x2B22D3EE`, hot
`0x7322D3EE`) → body/bounce/gloss paths (LinearGradient `0xFF1B2C48 → 0xF9060B14`, +`0x1A` bounce,
+`0x3DFFFFFF` gloss) → 1.1 dp glass arc → **2.2 dp rim stroke** → 2.2 dp track circle, 2.6 dp progress arc,
3.2 dp comet → 2.8 dp orbit arc → mark `Bitmap` clipped to a circle at `MARK_SCALE` (~0.53) → bars.
Geometry: `blob` lobing `a4=0.032, a2=0.018` (≤5 % → visually a circle); `r = (min(w,h)/2 − 6 dp) × 0.80`.

Material history: last face change **`b08879d` 2026-09-25 22:47**; `b08879d..HEAD` touches only
squash/lag fields, neutral shaders, comet/orbit arcs and the RETURN fade — **no change to body/gloss/rim
geometry**. So the material on the phone == the material in HEAD. And `b08879d` itself only re-parameterised
the same composition (circle→3 % blob, linear→sweep rim, 1.6→2.2 dp, +bounce +gloss) — the pre-9/25 face had
the same anatomy (halo + disc + rim stroke + glass arc + track + mark). **That is why the expected
transformation is not visible: the composition never changed.**

## 8. The minimum architectural change required

Both steps need the owner's go-ahead (nothing implemented in this audit).

**STEP 1 — put the newest binary on the phone** (removes cause #1): rebuild the debug/signed APK from HEAD
*including the uncommitted Wave 4*, install, and re-capture READY/AWARE/PAUSED/PROGRESS/RESOLVING/FAILED.
Required before judging the renderer — today **no binary contains Wave 4**.

**STEP 2 — replace `CoreHost`'s material vocabulary** (removes cause #2). Keep the state machine,
`CoreLook` tables, `CoreMotion`, `CoreArbiter`, `DowniCore` window and the service wiring — they are sound;
replace only the drawing:

1. **MembraneLayer**: a real annulus band (≈0.86–1.06 r): translucent cyan fill, bright inner-edge line,
   soft outer bloom; its brightness carries the wake energy (replaces the halo/stroke pair).
2. **RimLayer**: an extruded bevel in 3 passes (dark base, top-left light arc, bottom-right occlusion).
3. **BodyLayer**: lobing raised to the sheet's proportions (≈8–10 %), a *shaped* specular (arc/ellipse with
   a defined edge, 0.5–0.7 white), a bottom-right form shadow, teal internal light near the rim.
4. **MarkLayer**: composite the ribbon with a light pass and a glass overlay so it reads embedded (keep the
   R4 asset; measure `MARK_SCALE` against C1 ≈ 0.45–0.5 of the disc).
5. Only if Canvas still cannot hold fidelity at 32–42 dp: pre-render body+membrane+rim as sprites
   (512 master, or 1×/2×/3×) and keep procedural overlays for progress/orbit/tether/pulses.

**Explicit answer to the owner's question:** yes — **the renderer needs a substantial material rebuild**.
Tuning `CoreLook` alphas cannot produce C1. The wiring, states and tables do **not** need rebuilding.
