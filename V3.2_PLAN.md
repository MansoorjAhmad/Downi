# V3.2 PLAN — DOWNI Fetcher (floating zero-touch downloader)

**Status: Phase 0 ACTIVE — HARD GATE.** Owner approved 2026-09-24.
No feature code (bubble, wiring, polish) ships until Phase 0 reports its verdict.

## The feature (owner spec)

> Open Instagram/TikTok → floating bubble appears → video detected → bubble becomes
> ready → tap → download starts → progress stays synchronized with Downi, notification,
> Queue, and Vault.

## Locked rulings (2026-09-24, do not relitigate)

1. **Zero-touch required** — no copy-link, no share, no leaving the platform app.
2. **IG + TikTok only, videos only** (photo posts permanently out of scope).
3. **Tap-to-fire** — the bubble never downloads on its own.
4. **Pipeline is read-only reuse** — a resolved source goes through the existing
   `DowniDownloadService.startShared(context, url)` → Queue → notification → history →
   Vault (same saved file, no duplicates). The engine is not modified.
5. **Screenshots/visual analysis = spike diagnostics only**, never the production path.
6. **Local only** — accessibility data and spike logs never leave the phone; logs are
   deleted after analysis.
7. **Honesty rule** — if detection cannot be made reliable, we report exactly what
   failed; the bubble may never pretend to be armed when it isn't.

## Architecture (owner spec + layered-detection design, reconciled 2026-09-24)

```
AccessibilityService
 ├─ Layer 1: package detect (IG/TikTok foreground) → bubble appears (Phase 1)
 ├─ Layer 2: accessibility tree inspect → VideoCandidate {platform, id?, url?, confidence}
 │            └─ nothing found → bubble stays idle (honest, no fake armed state)
 └─ Layer 3: screenshot = Phase 0 diagnostic fallback only
TAP → SourceResolver(candidate)                 (Phase 2)
 ├─ resolves → DowniDownloadService.startShared → bubble ring ⇄ notification ⇄ Queue ⇄ Vault
 └─ fails    → bubble says "Couldn't detect this video" (plain sentence, house rule)
```

**Requirement split (the key insight):** "know I'm watching a video" (Layer 1–2, cheap)
is NOT "obtain the downloadable URL" (Layer 2–3, the unknown). Phase 0 measures the
unknown before anything is built.

## Phase 0 — Detectability Spike (HARD GATE)

**Question set (owner's four):**

| # | Question | Answered by |
|---|----------|-------------|
| Q1 | Can Downi detect Instagram/TikTok is active? | `SESSION_START pkg=…` logs |
| Q2 | Can Downi detect I'm actually watching a video? | `STEP2 watching_signals=[…]` vs browsing screens |
| Q3 | Is any useful identifier/URL for the current video exposed in the accessibility tree? | `STEP3 confidence=… url/id=…` |
| Q4 | Can that information reach the existing download pipeline? | `PIPELINE_READY` / `PIPELINE_HANDOFF …` |

**Method:** debug build only (`FetchSpikeService` — an AccessibilityService that logs,
never downloads). No bubble, no auto-grab, nothing user-facing beyond enabling the
service. Log file: `Android/data/com.omnidownloader.app/files/fetch-spike/spike_<ts>.log`.
Screenshots (API 34+, capability declared programmatically) saved under
`fetch-spike/shots/`, max 6/session, diagnostic only.

**Pipeline handoff gate:** default OFF — the spike only logs `PIPELINE_READY
contract=DowniDownloadService.startShared(url)`. To live-test Q4, create
`fetch-spike/spike_config.properties` with `handoff=true`; HIGH-confidence URLs then
fire one real grab each (owner-run experiment only).

**Device script (vivo V2058):**
1. Install debug build → Settings → Accessibility → **DOWNI Fetcher Spike** → ON.
2. Instagram: watch ≥3 feed videos (pause between), scroll across videos, open one
   profile, open comments once, back to feed.
3. TikTok: watch ≥3 For You videos with scrolls between, open one profile, back to feed.
4. Switch to a non-target app (ends session), then pull logs:
   `adb pull /sdcard/Android/data/com.omnidownloader.app/files/fetch-spike/ ./spike-logs/`
   (fallback: `adb shell run-as com.omnidownloader.app ls files/fetch-spike`).

**Phase 0 cells (defined before running):**

| Cell | Expect |
|------|--------|
| P0-1 | `SESSION_START` with correct package within ~1 s of opening IG/TikTok; no sessions from other apps |
| P0-2 | `STEP2` signals present while watching; absent/weak while browsing profiles/settings |
| P0-3 | `STEP3` candidates logged across ≥80% of watched videos, both platforms (measured, not hoped) |
| P0-4 | `PIPELINE_READY` logged for HIGH URLs; with `handoff=true`, grab reaches Queue + notification |
| P0-5 | Service stable: no crash, log cap respected, battery sane over a 10-min session |

**Verdict ladder:**

- 🟢 **GREEN** — Q3 reliable on both apps → design the production implementation from
  the actual log evidence, then Phase 1.
- 🟡 **YELLOW** — partial (one platform works / IDs but no URLs / signals only) →
  concrete gap report → **owner decision** on the residual gap before any Phase 1 code.
- 🔴 **RED** — no usable identifiers on either app → zero-touch source resolution is
  honestly reported as not technically available today. Options go to the owner:
  (a) bubble as "detects watching" only with the honest error, (b) re-open the assisted
  fallback ruling, (c) shelve the feature. **Never a silent pretense.**

## Phase 1 — Bubble shell *(gated on Phase 0 verdict)*

Overlay + drag anywhere + position memory + show/hide on target app + permission UX
(overlay grant screen, accessibility enable screen). States: idle / armed / busy.
Cells defined before code.

## Phase 2 — Pipeline wiring *(gated on Phase 0 GREEN/YELLOW plan)*

Tap → VideoCandidate → SourceResolver → `startShared()` → ring progress synchronized
with notification, Queue, history; Vault landing verified (same file, no duplicates).

## Phase 3 — Polish

Ring animation, glow when armed, honest failure reasons, edge-clamp smoothness,
tap-vs-drag discrimination, haptics per house style.

## Phase 4 — Device matrix → v3.2.0

Full DEVICE_TEST cells, signing-key check, tag → CI → release → updater feed.

## Rules of engagement

- Cells before code, every phase.
- "Verified is a fact, not a mood" — only cells dated ✅ on-device count.
- Debug/spike artifacts never reach a release build.
